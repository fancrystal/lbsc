# 礼包预约交易与积分商城：业务规则记录

更新时间：2026-11-08  
状态：需求讨论记录；仅记录当前确认内容，不代表开发规格已最终定稿。

## 一、产品与角色

系统包括面向用户的手机网页和管理员后台。管理员管理用户、礼包类型、礼包、积分、商品、匹配和异常订单。用户之间的交易由双方在线下或其他平台自行转账，平台不经手该笔交易款项。

“现金包”在本记录中统一称为“礼包”。系统有积分，积分可用于商城购买商品，也可冻结作为预约质押。不存在积分以外的独立质押金账户。

## 二、礼包类型与发放

- 管理员在后台配置固定的礼包类型，如现金1包、现金2包；启用后在前端展示并供用户预约。
- 每个类型设置初始价值、价值上限、日溢价率及预约所需质押积分。各类型独立配置；日溢价率初始可设为1%。
- 同一类型的礼包暂按统一初始价值发放。例如现金1包初始价值300、上限600。
- 管理员人工决定向哪些用户发放礼包、何时发放以及发放多少。注册后管理员也可直接给用户增加积分或发放礼包。
- 礼包默认处于寄售状态，但用户必须主动预约，才进入当天对应类型的匹配队列。持有天数不限制转出。
- 用户可以持有多个类型的礼包；若同类型存在多个可转出的礼包，具体优先选择哪个不重要，系统可按固定顺序自动选择。
- 管理员可收回用户账户中的礼包，不释放积分。后台记录操作人、时间和原因。处于交易或争议锁定的礼包如何收回，应先处理关联订单，避免账目冲突。

## 三、礼包价值与溢价

- 每天北京时间00:00自动按各类型的日溢价率复利计算，基数为礼包当时的当前价值。
- 每次计算结果四舍五入为整数，且不超过该类型的价值上限；达到上限后停止上涨。例如300按1%计算后为303，再次计算为306。
- 当天发放的礼包，从下一个00:00开始计算。礼包转让后保留已有价值和历史记录，继续计算，不重置周期或价值。
- 后台修改某类型的日溢价率或价值上限，从第二天凌晨开始影响已发放且尚未消耗或收回的同类型礼包，不回溯修改历史价值。
- 修改价值上限时，如果新上限低于该类型任何尚未消耗、尚未收回礼包的当前价值，后台拒绝保存并提示管理员。
- 交易或争议中的礼包跨凌晨时，礼包自身继续按规则溢价；对应订单已锁定的成交价不变。每次溢价应保存所用规则、计算前后价值和时间，供核对。

## 四、提货与积分

- 用户可对自己持有的可用礼包点击“提货”；系统按提货时的当前价值释放等额积分，并立即消耗该礼包。例如价值1100的礼包释放1100积分。
- 提货和积分发放应作为一次完整操作，记录流水，防止重复领取。
- 积分可用于商城购买商品，也可作为预约质押。冻结的质押积分不能用于商城购买或重复用于其他预约。
- 用户可按对方注册手机号互转正整数积分；仅可转出可用积分，冻结质押不能转出。转账即时到账，双方可在积分明细查看，系统记录转账编号并防止相同请求重复扣款。
- 管理员可对指定用户增加或扣减积分，记录数量、原因、操作人和时间；冻结中的质押积分不作为普通可用积分直接扣减。
- 原先暂定的16:00—22:00兑换限制取消。已有足够可用积分即可购买商品；处于交易或争议锁定的礼包在解除锁定前不能提货。

## 五、预约、匹配与质押

- 每种礼包类型有独立预约队列和匹配事件。用户可在同一天预约多个不同类型，但每种类型每天最多预约一次。
- 用户预约时，系统检查可用积分是否足够，并将该类型所需积分冻结为质押。不同类型各自冻结，不得重复占用。预约成功后用户不可主动取消，暂按此规则设计。
- 预约时间暂定每天北京时间00:00—16:00；16:00系统按类型分别自动随机匹配。16:00—16:10为匹配期，后台可选择具体礼包类型，多次点击按钮重新随机匹配该类型，其他类型不受影响；16:10自动固定最后结果，之后不能再改订单双方。时间暂定，建议后台可配置。
- 同一类型至少两名用户预约才可匹配；只有一人时取消该类型当日匹配，退回该用户冻结的质押积分。用户不能匹配自己。
- 每位预约用户同时获得一笔买入和一笔卖出订单。两人时互为买方和卖方。两笔订单分别处理，一个订单取消不自动取消另一个。
- 用户预约后，从预约时起锁定一个该类型礼包，锁定的礼包不能提货释放积分，直到交易完成。如果持有多个同类型礼包，其他可用礼包仍可提货。只有一人预约而无法匹配，或卖出订单因买方超时取消时，解除卖方礼包锁定，之后可以提货或再次预约。
- 用户没有礼包也能预约并参与随机匹配。结果固定后，如果某笔订单的卖方没有对应类型的可用礼包，该笔订单直接取消，买方本次预约冻结的质押退回。
- 匹配固定后，交易中的卖方礼包应锁定，避免同时提货或用于其他交易；匹配期的结果不作为最终交易依据。
- 每次后台重新匹配记录操作人、时间和结果。

## 六、用户间转让及异常处理

- 交易时间暂定16:10—22:00。16:10匹配结果固定时，以卖方礼包当时的价值锁定订单成交价格；该订单交易过程中价格保持不变。固定匹配后，买方查看匹配卖方的收款方式，在线下或其他平台向卖方转账。
- 注册时用户必须在微信、支付宝、银行卡三种收款方式中至少填写并提交一种；用户可在个人页修改收款方式，修改后仍至少保留一种。个人页的匹配订单可进入详情查看预约状态；匹配结果于16:10固定后，买方可查看卖方信息、成交价格及已填写的收款方式。买方转账后上传凭证并点击提交；卖方核实实际到账后点击确认通过。
- 买方必须选择转账截图才能提交；截图加密保存在服务器，卖方和管理员可查看。截图自上传起保留48小时，随后由系统自动清理；订单和交易记录保留。
- 卖方确认后交易成功，礼包转给买方；买方该次预约冻结的质押退回账户。
- 到22:00买方未提交凭证并点击提交：直接判定买方超时，扣除该笔预约冻结的全部质押；礼包解除锁定并仍归卖方。被扣除的质押不转给卖方。
- 买方如实际已转账但未在22:00前提交凭证，系统仍先按超时规则扣除质押。用户可点击申诉，由管理员结合实际情况核实并人工处理质押和礼包归属，记录处理依据。超时后卖方礼包解除锁定，可以提货或再次转让，申诉不额外锁定礼包。
- 用户自己的卖出订单未完成，不扣该卖方因本人买入预约冻结的质押；如对方作为买方超时，扣对方该笔预约冻结的质押。
- 买方已提交凭证而卖方到22:00仍未确认时，订单进入后台人工处理；买方质押继续冻结，直至处理完成。
- 后台核实转账成功，人工完成礼包过户并退回买方质押；核实转账未成功，则判定买方责任，按规则处理质押。后台须记录处理人、结果和依据。
- 后台应具备异常交易人工干预能力，可处理礼包归属及订单关联质押，保留完整记录。转账截图本身不等于实际到账证明。

## 七、积分商城与订单

- 管理员上架独立商品，例如礼品卡、蔬菜月卡／季卡／年卡、矿泉水月卡／季卡／年卡。同一商品的月卡、季卡和年卡作为不同商品，不做款式功能。
- 商品字段包括名称、积分售价、库存、封面、详情文字、详情图片、上架状态和排序；排序数值越大越靠前。管理员可新增、编辑、上下架商品及调整库存。
- 用户以可用积分购买；购买时校验商品状态、库存、积分和默认收货地址，成功后扣除积分和库存并生成商城订单。
- 订单保存下单时的商品、价格和收货地址快照。用户必须先设置默认收货地址。
- 发货、物流和异常情况由用户与管理员线下沟通，系统暂不设计发货、物流或退款流程。
- 管理员可在后台确认货到并填写提货码和留言发送给用户。用户在商城订单管理入口看到未读红点，进入订单详情可查看提货码和留言；查看后该订单红点消失。

## 八、用户端与管理端

用户端底部四个标签为首页、预约、商城、我的，整体视觉参考 `D:\work\cym` 项目。功能包括注册登录、按类型预约、我的礼包、匹配订单、互转明细、商城订单、地址管理、我的资料、修改密码和退出。积分及质押余额、变化记录应能查看；不采用参考图中未经确认的佣金等功能。

后台包括用户管理、礼包类型配置、礼包发放及收回、积分加减与流水、预约及随机匹配、交易订单及人工干预、商品管理、商城订单及提货码留言、管理员权限和操作日志。
