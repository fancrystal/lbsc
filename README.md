# 礼包预约与积分商城

本项目包含手机端、管理后台、Node.js API 和本地 SQLite 数据库。业务规则参见 `docs/业务规则记录.md`。这是本地开发版本，涉及用户线下付款和积分资产，上线前仍需完成业务验收、安全加固、隐私保护及法律合规审查。

## 启动

需要 Node.js 24 或更高版本。系统支持 6 至 128 位密码，包括纯数字。首次启动前，在 PowerShell 设置管理员账号和密码：

```powershell
$env:ADMIN_USER = 'admin'
$env:ADMIN_PASSWORD = '请替换为自己的强密码'
npm start
```

只有数据库尚无管理员时才会创建管理员；重启不会覆盖现有管理员密码。不要把真实密码写入项目文件或版本库。用户端为 <http://127.0.0.1:3100/>，后台为 <http://127.0.0.1:3100/admin>。服务默认仅监听本机。SQLite 数据位于 `data/app.sqlite`，并可能存在 WAL 辅助文件；备份时应先停止服务或使用 SQLite 在线备份工具，不要仅复制正在写入的主文件。

收款账号和付款凭证使用 AES-256-GCM 加密。默认密钥在首次启动时生成于 `data/app.sqlite.key`；也可通过 `APP_DATA_KEY` 环境变量指定 64 位十六进制密钥。应将密钥单独安全备份并严格限制访问；密钥丢失或更换后无法读取原有密文。密钥和数据库位于同一目录时，目录整体泄露仍会泄露资料；Windows 中应另外配置文件访问权限（ACL）。已有明文记录在启动时迁移，历史备份、旧 WAL 或其他副本也可能包含明文，应按敏感数据管理。

如 Docker 引擎可用，可设置相同环境变量后执行 `docker compose up --build`。容器端口默认映射到本机 3101，可通过 `HOST_PORT` 修改；数据库保存在本目录的 `data` 下。首次启动需要管理员密码环境变量。

## Git 与部署

上传前请检查 `git status`：`.env`、`data/`、数据库、密钥和 `backups/` 均不应提交。`.env.example` 是不含密码的配置模板；复制为 `.env` 后，在服务器本机填写管理员强密码。服务器必须保留 `data/` 持久目录，不能把数据库放在临时容器文件系统里。

```sh
cp .env.example .env
# 编辑 .env，填写 ADMIN_PASSWORD，并妥善保管 APP_DATA_KEY 或本地密钥文件
# 先创建 data/，确认容器内 node 用户对该目录有读写权限
mkdir -p data
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:3101/healthz
```

默认基础镜像为 `node:24-bookworm-slim`；如果服务器无法访问 Docker Hub，可将 `.env` 中的 `NODE_IMAGE` 改为可信镜像源的同一版本，再执行构建。容器以 `node` 非特权用户运行；在 Linux 上挂载的 `data/` 必须由该用户的 UID/GID（官方镜像通常为 1000:1000，需以实际镜像为准）可读写，目录权限应只授予必要人员。更改已有数据目录的所有权前先核对路径、现有权限并备份。`deploy/nginx.conf.example` 是 HTTPS 反向代理配置参考：须替换域名和证书路径，检查服务器已有站点与端口后再配置。容器映射只监听本机，不应直接暴露 API 端口。代理的 IP 必须按实际网络配置填写到 `TRUST_PROXY_IPS`，不要盲目设为所有地址。项目仓库附有 GitHub Actions 测试配置；上传 Git 后才会由 GitHub 执行，当前没有线上运行结果。

拟定用户端域名为 `lbsc.maishikeji.com.cn`，后台域名为 `albsc.maishikeji.com.cn`；对应的独立 Nginx 配置草案见 `deploy/lbsc.nginx.conf.example`。本项目计划与 cym 部署在同一服务器，但必须使用独立目录、数据库、环境文件和端口；3101 只是默认候选，部署前须在服务器确认未被占用。草案中的证书路径、DNS、可信代理 IP 及 ACME 验证方式均须以实际服务器检查为准；不能直接覆盖现有站点配置。

## 数据备份与恢复

在线备份工具使用 SQLite 备份接口读取一致快照，目标必须是不存在的新文件；目标目录需预先创建。例如在本机执行：

```sh
node packages/backend/src/backup.js data/app.sqlite backups/app-2026-11-08.sqlite
```

使用容器时可在容器内执行该命令，选择持久挂载目录中的新目标文件，再将备份安全转移到独立存储。备份数据库不包含 `data/app.sqlite.key` 或 `APP_DATA_KEY`，必须另行安全备份密钥。恢复前先停止所有使用该数据库的进程，将当前 `app.sqlite`、`app.sqlite-wal` 和 `app.sqlite-shm`（如果存在）一起保全到独立目录；确保原位置不再存在旧 WAL 和 SHM 后，才将经过校验的备份放到 `data/app.sqlite`，使用与备份对应的密钥启动。恢复操作应先在隔离环境演练，不要在生产数据上直接试验。

## 验证

```powershell
npm test
```

服务启动后每 30 秒检查北京时间的溢价、匹配、固定和超时任务，业务请求也会先检查任务；任务有持久化记录。停机错过匹配固定窗口时，预约取消并释放质押；停机跨越交易截止时间时，未付款订单转人工核实而不直接扣除。正常运行时定时触发可能有最多约 30 秒的延迟。

## 开发版限制

- 本版使用 Node 自带的实验性 SQLite 接口，适合本机开发验证；未完成生产级并发、故障恢复及性能验收。
- 不提供线上支付，付款截图仅供人工核对，不能证明实际到账。涉及异常申诉、原礼包已被提货或转走的情况，需由管理员根据线下核实结果通过现有积分调整和礼包管理人工处理。
- 已增加账号及来源地址的登录失败限流。反向代理部署时，可通过 `TRUST_PROXY_IPS` 指定以逗号分隔的可信代理 IP，只有来自可信代理的 `X-Forwarded-For` 才会被采用；不得将不受控制的地址配置为可信代理。多实例统一限流仍未实现。短信验证、实名校验、生产审计权限分级、备份管理及 HTTPS 等仍未实现，不得将真实用户资料或资金业务直接迁入本开发版。
- 预约、匹配和交易时间可在后台设置，按北京时间从次日生效；暂不支持跨午夜时段。
- 地址簿支持多个地址和一个默认地址；商品图片和交易凭证仍存储于本地数据库，尚未接入独立对象存储。
